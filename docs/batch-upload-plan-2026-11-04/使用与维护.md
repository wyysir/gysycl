# 十张独立单据录入：使用与维护

2026-11-04实施；演示服务器部署与最终公网检查以[发布记录](../releases/2026-11-04-batch-upload.json)为准。用户已授权部署，并追加确认图片压缩也包含在本次部署中。

## 使用方法

1. 进入“拍照录入”，选择项目点及备用日期。
2. 拍照或从相册追加，最多10张；开始前可移除或更换。每张照片对应一张独立单据。
3. 开始识别后逐张处理，按供应商连续查看明细；完整原单日期优先，缺日期沿用备用日期。
4. 点材料行弹窗编辑，对照本张原图；支持保存本行、保存并下一行。供应商、日期、总额和材料关联在弹窗处理。未知供应商或材料需要员工确认关联或新建。
5. 每单完成后点“确认本单”，再点“提交已核对的N张”。成功进入主管审核，有问题或提交失败的仍留在批次。修改后须重新确认。

刷新或重新进入“最近批次”可继续已上传的单据；未上传的图片可能需要重新选择。重试只针对未完成项，不会重复建单。正在识别的单据五分钟内不能再次触发模型；超时后需明确点击重试。历史多页单据保持原结构。

## 压缩与原图

- 上传前对不小于1.2MiB的文件尝试JPEG质量0.91、最长边3000像素，不放大；只有输出更小时才采用。小文件、解码失败或浏览器不支持时保留输入文件。
- 同时处理两张，避免十张大图一起占用手机内存；服务端识别继续使用原有3000/91处理基线。
- 网站“原图”是实际上传版本。大图成功压缩后，不另传手机未压缩文件；手机本地文件不修改，历史图片不重压、不清理。HEIC暂不接收，应转换为JPG，微信实际选图行为待真机确认。
- 浏览器验证：两张已有图片无损转PNG后由4,240,948/4,018,359字节压至522,583/648,536字节，约减小87.7%/83.9%；4032×3024测试图缩至3000×2250。该PNG测试用于触发压缩分支，不代表所有手机JPEG都能减少相同比例。
- 两张压缩图再次经过真实模型后，品名、单位、数量、单价、金额、日期、总额与本轮未触发客户端压缩的基线一致。样本仅两张，不能保证所有小字、模糊字均不受影响。

实测当前OSS对象有版本ID，禁止覆盖请求头在版本控制桶中无效。因此完成上传时将校验后的字节保存到新的服务器专用原图键，再建单引用；浏览器上传签名只操作临时键。真实浏览器重放旧签名返回200，但已建单原图SHA256未变化。

11月4日修复补充：临时上传只签名并发送Content-Type，不再携带x-oss-forbid-overwrite。现场跨域预检显示后者使OPTIONS返回403，浏览器因此显示“网络错误”；仅Content-Type预检返回200。不得为此移除服务器专用原图冻结步骤。桌面与模拟安卓微信浏览器验证、部署镜像及备份见[上传修复发布记录](../releases/2026-11-04-upload-cors.json)，实体手机仍须用户复测。

临时键尽力删除。现有OSS版本历史仍由桶配置保留，删除当前对象不等于回收历史版本空间；本轮未改生命周期或删除业务历史版本。测试对象已从当前可见对象中清除，历史版本可能仍占空间。后续存储方案应专门处理临时键与非当前版本保留期限。依据：[OSS PutObject](https://help.aliyun.com/zh/oss/developer-reference/putobject)，2026-11-04打开核对并实测。
