## 5. 后续工作流程与节点

时间均为**建议的工作日目标**，不是开发方已承诺的日期。T0为验收会议确认基线并分派责任人的时点；无具体负责人的任务不得进入“已安排”状态。

### 5.1 流程及状态

`登记 → 需求/复现确认 → 指派 → 修复及代码审查 → 提交可部署版本 → QA定向回归 → 全量回归 → 预发布补验 → 业务确认 → 交付签字 → 上线/移交`

- **开发负责人**对修复结果负责，可以使用DeepSeek执行修改，但必须提供人工审查人；模型本身不能承担交付签字责任。
- **QA负责人**维护唯一台账、执行回归、出具复测结论；不能由开发自测替代。
- **业务负责人/采购/主管/财务代表**确认规则、人工确认流程及实际操作结果。
- **运维负责人**提供预发布环境、云资源、配置核对、备份恢复、告警及回滚证据。

### 5.2 修复提交与回归方式

每个缺陷状态使用：`未修复 → 修复中 → 待复测 → 复测通过/重新打开 → 已关闭`。开发提交“待复测”时必须附缺陷ID、根因、修改文件、提交/制品哈希、自测结果和配置/迁移变化，QA验证后才能关闭。

1. 先按台账中相同角色、数据、操作和期望状态码执行定向回归；金额、权限、审核问题同时核对数据库实际值和日志，不只看页面提示。
2. 权限修复使用“角色×项目×创建者×状态”组合；拒绝请求要证明没有写入。金额规则覆盖0、正常值、边界小数、含税约定；主数据覆盖同名多规格/多单位。
3. 并发与重试在PostgreSQL和实际Redis Worker上再次执行，增加多个Web实例、保存与审核交错、OCR重复投递和任务中断后恢复。
4. 回归完整运行原有测试和本报告新增测试、构建、类型检查、HTTP主验收、数据勾稽以及工作页面；失败断言不得删掉或放宽以“变绿”。需求变更必须先签认并修订标准。
5. 外部OCR采用固定、脱敏、带人工真值的盲测集；调整模型或提示词后重新全量盲测；Mock和离线故障注入不计入准确率。

### 5.3 交付确认条件

- 阻断、严重缺陷全部关闭；一般缺陷原则上关闭。确需延期的P2必须明确影响、替代方案、负责人、到期日，由需求方书面接受；权限、账务和监管必需项不能降级放行。
- 所有纳入交付的模块有明确通过结论；上述外部补验无空白项。达不到真实识别阈值时不得以“演示可运行”代替交付。
- 使用同一冻结版本完成复测；代码、构建、迁移、配置和文档可追溯；净环境安装与部署可复现。
- QA、业务及运维共同确认，项目负责人签署最终验收；存在一般遗留项时明确“有条件通过”的到期条件。本轮版本的结论仍为“不通过”。

## 6. 上线/移交前检查清单

- [ ] **版本**：Git tag/提交或不可变源码包、制品SHA-256、依赖锁、发布说明、回滚版本齐备，修复项对应版本一致。
- [ ] **配置**：DEMO_MODE=false；真实OCR；独立强随机SESSION_SECRET；APP_URL/HTTPS正确；不带演示账号；云密钥使用最小权限且不进入源码/报告。
- [ ] **数据**：项目、用户角色、供应商、材料和合同价由业务核对；同名多规格、日期区间正确；演示数据不进入正式账目。

- [ ] **权限**：匿名401、跨项目403；财务所有写入口被拒绝；已审核数据所有旁路保持受控；导出和私有图同样校验范围。
- [ ] **识别与流程**：盲测逐字段达标；低置信确认可追溯；保存/提交/退回/重提/普通和强制审核均通过；OCR失败保留原图且可恢复。
- [ ] **任务队列**：Redis连接、Worker存活、重试/失败队列、积压报警、重复任务幂等和中断恢复验证完成。
- [ ] **微信与存储**：授权域名和公众号菜单正确；首次绑定与模板通知实测到达；OSS私有、CORS最小化、签名过期有效；生产图片不可公开访问。
- [ ] **性能与稳定性**：G0约定数据量、并发、响应时间、持续时长和错误率；预发布实测满足；真实云耗时/队列延迟纳入观察。
- [ ] **监控**：健康检查、5xx、OCR失败率、队列积压、数据库连接、磁盘容量有告警，并实际触发一次验证接收人。
- [ ] **备份恢复**：按文档落实5年业务/图片保留、RDS每日备份30天、月度归档；完成从备份恢复的演练并签认RPO/RTO。
- [ ] **上线**：变更窗口、操作人、备份点、回滚触发条件、演练结果和上线后冒烟清单明确。
- [ ] **移交**：部署/恢复/告警/账号管理SOP、数据字典、接口文档、环境清单、值守升级联系人及业务培训齐全；密钥通过独立安全渠道交接。
- [ ] **签字**：需求方、交付方、QA、运维和项目负责人签认；一般遗留项有责任人、截止日期和补验节点。
