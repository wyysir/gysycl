# 草稿与误传图片直接删除

日期：2026-10-29。用户明确要求“新增草稿删除，不需要做回收站，草稿页面可以删除误传的图片”。功能已上线，21:25 北京时间核对业务库/图片保留一致；Web/Worker 镜像均为 1dec3484b9d2，代码提交 54d3273。见[发布记录](../releases/2026-10-29-draft-delete.json)。

## 使用方法

1. 打开一张“草稿”单据。管理员、或有项目提交权限的草稿创建人可以操作；财务、其他创建人及无项目权限的账号不显示删除入口，接口同样拒绝。
2. 要删误传图片，先切换到对应图片页，点原图下方“删除此图片”。
3. 确认框说明将删除哪一页、对应多少条来源明细；点击“取消”不删除。点击“确认删除图片”会先保存其余未保存修改，再删除目标页。
4. 能明确关联该页的识别明细一起删除，其余图片、明细、人工校正保留；页码及明细序号重新连续编号，各页原日期/单号随图片保留。
5. 删除图片后，整单总价暂置 0 并明确提示重新核对，不自动从独立原单总价中减去猜测金额。检查剩余明细并填写整单总价后再提交。
6. 旧明细缺少来源页时不猜测删除，保留并提示人工核对；你可从明细卡片移除误传图片对应的行。
7. 要删整张误传或重复草稿，点页面上方“删除草稿”，核对图片和明细数量后确认。删除后返回单据中心，草稿及图片/明细记录从业务列表移除。
8. 草稿只剩一张图片时，“删除此图片”会明确提示同时删除整个草稿；确认后不留下空壳单据。

**不设回收站，不能从页面恢复。** 系统保留操作审计，但不提供作废列表或恢复按钮。请按确认框核对后删除。

## 处理边界

- 仅 DRAFT 草稿可直接删除。识别中、待审核、已通过、退回补充状态不开放直接删除；不能用图片接口绕过审核状态。
- 删除需要当前版本；另一窗口已修改、识别任务已开始或单据已提交时返回冲突，先刷新，避免误删新内容。
- 共享同一个存储文件的其他单据会继续保留该文件。相同内容但不同存储文件分别处理，不按图片摘要批量删文件。
- 删除重复草稿或图片后，会重新计算相关未通过单据的重复提醒；不需要为清除旧重复图片错误而强制审核。已通过历史检查不会被重新打开。
- 删除不自动触发收费 OCR，也不自动审核、撤回或删除另一张草稿。本次上线只提供按钮，不替用户选择并删除线上记录。
- 本功能沿用财务只读、已通过先撤回再改等规则；撤回并不自动使记录成为可删除的 DRAFT。

## 维护说明

新增 DELETE /api/documents/:id 及 DELETE /api/documents/:id/pages/:pageId，JSON 请求必须携带 version。服务端独立检查身份、项目/创建人权限、草稿状态、版本和图片归属。

草稿整单实际删除，不增加 deletedAt、回收状态或新表。历史审计解除对已删除单据的外键，保留原实体编号及删除操作；如草稿曾有审核历史，删除审计中保留该历史摘要。已通过单据本身不能被本接口删除。

单页删除在事务中更新图片、来源明细、连续编号、总价和操作记录。原单日期/单号使用现有 DocumentPage.ocrRaw 保存；兼容上一版 OCR 审计中的逐页信息，不新增数据库迁移。

数据提交后再清理无引用的原图和处理图，避免事务失败时先删图片。存储不可用时业务记录仍删除，返回文件待清理提示并记录 storage.cleanup_failed；管理员恢复存储后按操作记录核对引用再清理。若关联提醒刷新失败，返回提示，可在保留单据点“重新比对”。不把这些失败误写成业务删除已回滚。

更新前按既有维护流程备份数据库和图片并保留旧镜像。界面回退只切换 Web/Worker；不会恢复用户已删除的草稿，恢复业务数据须从独立备份另行评估，避免覆盖后续数据。

本轮更新前备份 /opt/delivery-audit/backups/20261029-212150，电脑副本 .data/server-backups/20261029-212150，三个文件 SHA256 一致且压缩包/图片归档可读；旧镜像 delivery-audit:before-draft-delete-20261029 保留。无新增迁移。旧版未读取持久化页来源字段，回退后原日期/单号展示需额外核对。
