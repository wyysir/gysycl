# 2. Bug 记录与修改方向

## 2026-10-30 用户反馈：跨日期同号缺少重复提醒（待复现/修复）

逐项验收时，用户对同供应商、同单号、日期不同的情形反馈“不提示重复，但能普通审核”。预期应提醒重复且允许提交和普通审核；当前缺提醒为待修复问题，普通审核通过本身不是问题。尚未取得具体单据、未定位根因；后续核对供应商归属、单号保存值、查询日期范围、检查结果及页面展示，不预断为某一层故障。不为复现擅自修改真实业务单据。该反馈不改变此前自动化通过的历史记录，也不能用历史测试替代本次实际验收。

下列每一项对应质量报告中的 B 编号。“已修复”指本次代码修复，部署结果另见发布记录；不会把旧版本的缺陷写成当前仍存在。

## B01 · 增删明细未标记未保存（中，已修复）

- 触发：草稿中增加一行或删除一行，立即点击返回。
- 根因：这两个处理器直接 setData，没有走 updateItem，漏掉 setDirty(true)。
- 修改：`documents/[id]/page.tsx` 的增加一行、DocumentItemsEditor.onRemove 入口置 dirty，忙碌期间拒绝修改。
- 验证：隔离浏览器增加行→返回出现未保存弹窗→取消保留编辑；删除路径人工审查同样置 dirty。

## B02 · 重新比对丢失未保存修改（高，已修复）

- 触发：修改备注、数量或金额但不保存，点击“重新比对”。
- 根因：recheck 仅重新计算数据库旧值，随后 setData(result) 覆盖内存新值。保存期间继续输入也可能被响应替换。
- 修改：`documents/[id]/page.tsx/recheck` 先 await save(true)，失败即返回，再请求比对；加 rechecking/busy，禁用字段和明细编辑，成功重置 dirty。
- 验证：修改备注后重新比对，服务端与页面均保留新值；无静默回退到旧备注。

## B03 · 审核详情响应乱序（高，已修复）

- 触发：网络较慢时依次选择 A、B，A 的响应最后到达。
- 根因：loadDetail 未检验响应是否属于最后一次选择，旧结果可覆盖新结果；审核按钮使用当时 detail。
- 修改：`reviews/page.tsx` 用 detailSequence 丢弃旧响应、开始加载清空详情；渲染和 review 操作均要求 detail.document.id === selectedId。
- 验证：浏览器人为延迟 A 请求 800ms，最后选中 B 时预览保持 B。

## B04 · 队列切换仍显示另一队列详情（中，已修复）

- 触发：选中待审核记录后切到“已退回”，或当前队列没有单据。
- 根因：选择有效性在 pending+returned 合集中检查，并有跨队列回退候选。
- 修改：`reviews/page.tsx/loadReviews` 只在 data[tab] 中保留/选择 ID，空数组使用空 ID；loadDetail 空 ID 清空预览。URL 的 doc 也必须属于当前队列。
- 验证：补充隔离浏览器空队列检查；后续如需从 doc 参数直接打开另一个队列，应显式切 tab，不能恢复跨队列兜底。

## B05 · 非法 Logo 选择仍保留旧待上传文件（中，已修复）

- 触发：先选择合法 JPG，再选择 TXT 或超限文件，然后点击保存。
- 根因：错误分支仅显示错误、清空 DOM input，没有清 React file。
- 修改：`BrandSettings.tsx/onChange` 同时 setFile(null)，取消预览并禁用保存。
- 验证：有效图→非法文本后预览消失、保存禁用，已保存 Logo 不变。

## B06 · SPA 历史后退丢失未保存内容（中，已修复并上线，真机验收待完成）

- 复现：列表进入单据，修改字段/明细/备注或审核说明，不保存，使用浏览器后退、前进、手机返回手势；录入页选择图片/日期后返回也存在同类问题。
- 根因：原实现仅监听锚点 click 和 beforeunload；同文档历史遍历不触发二者。字段和 File 仅在组件 state 内，离开卸载就丢失。当前 Next 的 popstate 监听先执行还会提前清理编辑页，因此不能在普通 effect 尾部才安装拦截。
- 已执行修改：
  1. `src/lib/client/history-guard.ts/installHistoryGuard` 在布局阶段先注册 popstate，再接入 Next 的 push/replace 包装；保留路由内部 state，只给真实历史项加序号。先恢复原位置再询问，确认后按原 delta 跳转；连续返回合并处理，不插入虚假历史项。
  2. `src/components/LeaveProtection.tsx` 统一站内链接、历史导航、关闭/刷新提醒与退出提示。提供取消、暂存并离开、放弃修改并离开、适用时保存并离开；失败继续留页，保存/上传中禁用离开操作；手机弹窗按钮竖排，含焦点约束和 Escape。
  3. `src/lib/client/draft-store.ts` 使用 IndexedDB 保存字段与图片原始字节/文件名/类型/修改时间，读取时重建 File，兼容拒绝直接存 Blob/File 的 WebKit。按账号、标签页会话及单据隔离；串行写/删防止旧写入复活，保留 12 小时，到期不恢复、下次访问清理。保存、上传、明确放弃和退出会清理；不存密码，不进入服务器，不写图像 base64 到 localStorage。
  4. 详情与录入页接入恢复机制。详情按单据 ID、版本、状态和权限校验，冲突保留原输入供查看，不覆盖服务器；轮询不覆盖 dirty 内容。上传失败保留文件，成功清理副本及旧弹窗，返回不会再次提交；上传期间锁定项目/日期/图片移除。
- 修复中发现并处理：快速返回中断 history.go、WebKit File 写入及释放后重复读取失败（内存也改存原始字节，重入重建 File）、手机四按钮横向溢出、图片预览 URL 清理时机、恢复明细合计。它们均归入 B06 回归，不作为仍未处理的线上 Bug。
- 验证：125 项自动化测试、TypeScript、生产构建；Chromium 和 WebKit 各 21 项手机尺寸浏览器回归通过。覆盖多次/快速/跨两项历史返回、前进重入、刷新/跨文档恢复、保存失败/成功、存储配额失败、版本冲突、原图 SHA-256、独立标签页、跨账号、退出、上传失败/成功中返回、过期清理。无付费 OCR；详见 `b06-validation-summary.json`。
- 实际边界：未知/跨文档历史由浏览器原生提示和恢复副本兜底，不能保证每种浏览器都显示提示；用户主动清除浏览器存储、系统在首次持久化完成前强杀进程无法保证恢复。安卓系统返回、iPhone 边缘滑动、微信内置浏览器以及复制标签页/重启恢复须实机验收，详见 H02/H03。不要把桌面移动模拟说成实机通过。
- 2026-10-30 02:19（北京时间）公网6项检查通过，未提交任何业务修改；11单/78行/24页、103审计、48图片及Logo摘要保持不变。发布状态：以 `../releases/2026-10-30-navigation-recovery.json` 和对应 Git 标签为准；本节代码验收不替代发布证据。

## B07 · 手动供应商查询缺少异常处理（中，已修复）

- 触发：供应商查询接口超时/返回 5xx，点击查找或回车。
- 根因：两个事件分别 await/then，无 catch，产生未处理 Promise 拒绝且用户无反馈。
- 修改：`documents/[id]/page.tsx/searchSuppliers` 统一封装查询与错误 Toast，两个入口复用。
- 验证：模拟 503 返回“模拟查询失败”，页面显示错误且无 pageerror。

## B08 · 审核队列硬编码置信阈值（低，已修复）

- 触发：将 `OCR_CONFIDENCE_THRESHOLD` 调整为非 0.9 后，查看队列中的置信度颜色。
- 根因：队列使用 `item.confidence < 0.9`，详情和后端使用环境配置。
- 修改：`api/reviews/route.ts` 返回 thresholds.ocrConfidence；`reviews/page.tsx` 使用返回字段。
- 验收：接口值与配置一致，前端无硬编码；调整阈值的真部署应另行验证全部历史校验是否需重算，不能仅改颜色就称风险数据更新。

## B09 · 取消后同一 Logo 文件可能无法重选（低，已修复）

- 触发：选图→取消选择→从文件对话框再选同一路径。
- 根因：React file 清空，但原生 input.value 仍是该路径，浏览器不触发新的 change。
- 修改：`BrandSettings.tsx` 增加 inputRef，取消、保存成功时同步清空 value；非法选择已有清空逻辑。
- 验收：取消后 input.value 为空，能重新选择同一图片并出现预览。

## B11 · 过期详情加载响应覆盖恢复内容（中，已修复）

- 触发：开发严格模式双重挂载，或详情重入产生重叠请求；先读取并恢复备注，较早的初始读取随后返回。
- 根因：`load()` 每次请求返回后无条件 `setData` / `setDirty(false)`，不区分是否仍是当前请求。
- 修改：`documents/[id]/page.tsx` 的 `loadSequence` 在开始请求时递增；写状态和显示错误前校验序号；加载 effect 清理时使旧序号失效。该保护与B06版本检查共同工作，不把恢复副本视为服务器已保存。
- 验证：开发预览21项恢复检查通过；生产 Chromium/WebKit 各21项覆盖重入、历史前进、刷新、版本冲突和原图字节。

## B12 · 相同价格误标为相对最高（低，已修复）

- 触发：矩阵某材料只有一个有效项目价格，或所有项目价格相等。
- 根因：仅判断当前价格等于 max，没有确认 max 与 min 存在差异。
- 修改：`analytics/page.tsx` 单元格高值条件增加 `max > min`；无价格仍展示“—”，不转0。
- 验证：隔离分析中单项目材料保持中性；青菜不同价格仅较高项使用浅金。选中边框仍表示用户选择，与相对高值是两个状态。

## B13 · 小于1元的价差柱缩放失真（低，已修复）

- 触发：当前材料最大价差仅0.10或0.50元。
- 根因：原 `Math.max(1, ...spreads)` 强行把分母设为至少1，最长数据柱不能充满比例尺。
- 修改：`analytics/page.tsx/maxSpread` 改为实际最大价差，全部零时使用0.01兜底；零价差保留空轨道。
- 验证：当前0.10价差显示为最大长度，0.00为空轨道；采购金额和数据口径未变化。

## B14 · 上传成功后的历史返回进入旧上传页（中，已修复）

- 触发：工作台进入上传，建单成功后点击浏览器后退。
- 根因：成功跳转使用 `router.push`，已提交上传页仍在历史栈中；虽然B06清空了文件，路径仍与方案不符。
- 修改：`upload/page.tsx` 成功分支使用 `router.replace`；保留已有恢复记录 createdId 的 replace 路径。详情界面返回按钮默认进单据中心，浏览器后退回上传前的有效历史来源。
- 验证：更新 `scripts/verify-recovery.mjs` 成功上传断言；两引擎均验证后退回工作台，再新开录入页时无旧图、无重复建单。

## B15 · 浮点小数未补足两位显示（低，已修复）

- 触发：金额/单价填写1.1后离开输入框。
- 根因：新展示组件用 `Number.isInteger(value * 100)` 判断是否两位内，1.1×100可能为110.00000000000001。
- 修改：`AmountInput.tsx` 用 `Number(value.toFixed(2)) === value` 判断，仅显示时补两位；超过两位的实际单价原样保留，编辑中的原文本也保留。
- 验证：浏览器1.1离焦为1.10；4.2567折叠、再展开和查看原图后仍为4.2567。

## B16 · 抽屉跨断点后页面仍被锁滚动（中，已修复）

- 触发：768–1439px打开依据抽屉，再旋转/缩放至手机或≥1440px。
- 根因：打开时一次设置 `body.style.overflow=hidden`，后续布局改变未同步解除。
- 修改：详情依据effect监听中屏 `matchMedia` 的 change，只在中屏锁滚动；关闭/卸载移除监听、恢复原值和触发焦点。
- 验证：中屏打开锁定；Escape关闭释放；再次打开缩至390px即释放，手机仍可关闭依据区域。
