## 更新规则

1. 开始前查看 `git status`、最近提交与标签，保护其他工作区改动。
2. 完成授权修改，运行适用检查，更新维护说明和[CHANGELOG](../CHANGELOG.md)，选择性暂存并提交。
3. 上线前备份数据库及图片、保留旧镜像，核对迁移和业务保留证据。
4. 上线完成后在 `docs/releases/` 记录实际源码、镜像、源包摘要、迁移、验证、备份与回退依据。
5. 建立独立注释标签 `release/YYYY-MM-DD-简短名称`，同日追加使用不同名称或递增后缀，旧标签不可移动或覆盖。
6. 提交号从Git查询，不在同一提交内填写自身哈希。仅本地清理或文档修改不创建上线标签。

规则来源为根目录[AGENTS.md](../AGENTS.md)。历史未提交的上线仅按已有镜像和实际证据登记，不伪造提交或倒填时间。

## 回退与数据边界

Git保存源码、脱敏证据与文档，不保存真实送货单图片、数据库、密钥和私有配置。回退应用时按对应发布记录处理Web/Worker，保留数据库和图片卷；不要用旧数据库覆盖后续业务。数据库恢复需要单独的备份依据和授权，不能与界面回退混为一谈。
