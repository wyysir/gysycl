## 第一阶段：你先准备业务资料

- [ ] **确定对接人。** 填清业务负责人、主数据整理人、技术实施/运维负责人、采购财务对接人；每项有人接收问题和确认结果。完成标准：四项职责都有姓名与联系方式，同一人可兼任。
- [ ] **选定第一批试用项目点。** 先列试用点及负责采购、主管、财务，再列其余项目的推广顺序。完成标准：试用名单和负责人员明确，有人能配合真实单据测试。
- [ ] **收集至少 30 张真实送货单作为识别盲测集。** 覆盖主要供应商、不同手写字迹、表格样式和清晰度；包含单页、多页、跨日期同号等情况。脱敏时保留测试需要的供应商对应关系、日期、单号、品名及数字，不改变原有字迹。完成标准：图片有固定编号，多页按顺序归到同一单据。
- [ ] **给测试单据制作人工标准答案。** 逐单核对供应商、日期、单号、规范品名、规格、单位、数量、单价、行金额和总价。完成标准：图片编号与标准答案一一对应，由业务人员复核，不能直接把 OCR 输出当答案。
- [ ] **整理正式主数据。** 准备项目点编码与名称、供应商名称与别名、原材料名称/规格/单位/分类/别名、项目合同价及有效期。优先消除同一物料不同叫法和单位混用。完成标准：可按系统三张 Excel 模板导入，并有人确认合同价来源。
- [ ] **整理正式账号与权限表。** 列员工号、姓名、全局角色、负责项目、采购或主管角色；确认各项目谁上传、谁审核、财务谁只读。完成标准：员工号唯一、项目关系完整，有新员工开通和离职停用的负责人。

## 第三阶段：交给实施人员或运维完成部署

- [ ] **交付最新源码版本。** 本次修复及重复单号新规则应进入同一个发布制品；记录版本标识和校验值。完成标准：Web 与 Worker 使用相同版本，避免发布旧交付包中的业务代码。
- [ ] **部署应用、Worker 和数据服务连接。** 按已选部署方案验证 PostgreSQL、Redis、私有 OSS 与服务器之间的实际连通性。完成标准：生产服务启动，健康接口正常，真实任务通过队列到 Worker 并写回数据库。
- [ ] **核对正式配置。** 正式环境使用 `DEMO_MODE=false`、`OCR_MODE=aliyun`、`STORAGE_DRIVER=oss`，以及实际的数据库、Redis、会话密钥、模型与接入地址。完成标准：没有模板占位值，业务页面不以 Mock 结果冒充真实识别。
- [ ] **完成域名、HTTPS 与手机访问。** 核对实际域名、反向代理、上传请求限制及证书续期方式。完成标准：手机移动网络可打开正式 HTTPS 地址，登录、上传与看图正常。
- [ ] **创建正式管理员并导入主数据、账号与项目权限。** 正式库不执行演示 seed 或 reset；模板先校验、再正式导入。完成标准：真实项目、员工、供应商、物料、合同价齐备，能用正式账号登录。
- [ ] **完成 OSS 上传及私有图片权限验证。** 测手机直传、应用读图、签名过期和项目隔离。完成标准：所属项目能用图，未登录及其他项目账号不能越权访问或引用图片。
- [ ] **完成微信授权、绑定与通知联调。** 由公众号管理员及测试员工配合，实测提交后的主管通知、通过/退回后的员工通知。完成标准：手机实际收到消息并能回到正确单据；未完成时不能标记微信通知已验收。

以上是需要完成的结果，不要求你亲自敲部署命令。你需要协调账号、资源、资料和能够操作它们的人。

## 第四阶段：你组织业务人员做真实验收

- [ ] **组织真实 OCR 盲测。** 使用第一阶段的固定样本和人工答案，分别统计品名、数量、单价、行金额、整单总价及日期。完成标准：按项目既有验收要求逐字段达到 95% 以上，并保存错例；不能以本地 Mock 或“看着差不多”替代。
- [ ] **验证采购→主管→财务完整闭环。** 采购上传校正、提交，主管修改/退回，采购补充重提，主管通过，财务查看和导出。完成标准：各角色都实际操作，字段、状态、权限及操作记录正确。
- [ ] **验收已确认的两项流程。** 低置信度仅提示、可提交；同供应商同单号跨日期仅提醒、可普通审核。完成标准：两项均有实际通过用例；同时存在独立金额/合同价等严重异常时，仍按原规则处理。
- [ ] **核对合同价及多项目比价。** 选几种真实原材料，核对名称、规格、单位、合同有效期、供应商及项目范围。完成标准：相同口径可比，不把不同规格或单位混成一组。
- [ ] **核对导出与业务金额。** 由财务对照原单检查 Excel 单据汇总、明细和异常三张表。完成标准：金额和行数一致，日期、供应商、项目及筛选范围正确。
- [ ] **验收真实云环境的峰值与故障恢复。** 让实施人员按实际并发和单量测试排队、限流、超时、重试与重启。完成标准：有云端记录与结果；本机 100 次读取的结果不直接充当正式容量承诺。
- [ ] **安排备份和恢复演练。** 由运维备份后恢复到独立环境，核对单据、原图、审批和审计。完成标准：记录实际恢复点与耗时，验证既有方案的 RPO 15 分钟/RTO 60 分钟目标是否达到；未实测前不算达标。

- [ ] **启动已选项目点的小范围试用。** 每位参与者知道如何登录、拍照、校正、提交、审核、退回和导出。完成标准：正常业务实际跑完，问题有编号、图片或步骤及负责人。
