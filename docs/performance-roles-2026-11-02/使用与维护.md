# 自定义角色、搜索与性能维护

2026-11-02：已部署当前试用网页，公网检查通过，证据见[发布记录](../releases/2026-11-02-perf-roles.json)。当前网页仍是测试和演示环境。

## 管理员如何配置

1. 打开「系统设置 → 角色权限」，填写角色名称，勾选需要的权限并保存。可以套用员工、主管模板后调整，也可以从空权限开始。
2. 在「员工账号」新建员工，或点击已有员工的「设置项目角色」。每个项目点分别选择内置或自定义角色；同一员工可以在多个项目担任主管，也可以在另一项目担任员工或只读角色。
3. 修改角色会影响所有使用该角色的项目授权；停用角色后，相应授权立即失效。服务端每次请求读取当前权限，已经打开的页面需刷新以更新按钮。

首次部署可独立配置20项业务权限，后续新增4项查看权限共24项，现行说明见[查看权限与检索维护](../view-permissions-2026-11-02/使用与维护.md)：上传/手工建单，修改自己的或项目内的单据，提交自己的或其他人的单据，重新识别，校正待审核单据，通过、退回、强制通过、撤回，删除自己的或项目内的草稿/退回单，导出，价格分析，项目合同价维护，以及共享基础资料的新建、修改、导入。

现行自定义角色分配到项目后，默认仅查看本人的单据，单价、金额、合同价、他人单据需分别勾选；不再沿用首次发布的全项目只读默认。原材料、供应商全公司共享，勾选相关维护权限会影响全公司资料，界面已有提示。合同维护、合同导入及单据操作按项目授权。

账号、角色、项目及品牌设置仍由系统管理员管理；财务保持全项目只读、查询和导出。内置项目主管现在也可上传和手工新建单据。自定义角色不会继承底层兼容字段的员工权限。

权限不会跳过业务约束：已通过单据需先撤回才能修改，删除仅限草稿/退回状态；重新识别还需要修改权限；强制通过还需要审核通过权限并填写原因。所有写入继续校验项目、单据状态、版本和审计记录。

## 搜索与性能变化

2026-11-02用户确认：上传识别速度没有问题，此前变慢是开启代理导致，该速度反馈已关闭。本次仅更新用户反馈，未重新计时或调用收费模型；识别准确率、iOS兼容及大数据/并发专项仍按原范围待验收。

- 供应商直接在输入框检索，输入停顿250毫秒后查询；移除「供应商」标签和「查找供应商」按钮，保留当前选中供应商及匹配状态。
- 单据中心和原材料搜索框移除放大镜与额外占位，避免手机上图案重叠；价格分析的独立查询按钮保留。
- 常用页面只加载上下文，避免每次携带整套供应商、材料及合同；识别轮询复用已有上下文；增加页面切换加载反馈。
- 上传继续保持3000像素上限与JPEG质量0.91；最多两张并发上传，保持页序，失败时停止新任务并等待进行中的请求结束。压缩后更大则使用原文件，不降低既有识别清晰度设置。
- 图片预处理结果复用；同一单据的材料匹配只读取一次目录，名称与拼音转换在该次匹配内缓存。模型、提示词、每图一次请求及不自动收费重试的规则保持。

服务器抽查未发现资源不足或识别排队，历史最近识别任务约6至17秒。网络、手机和外部模型均影响体验；桌面浏览器模拟手机宽度不能代替用户真机验证。本次没有调用收费模型，不能声称外部模型耗时已实测改善。

后续可从Worker日志 `ocr.timings` 查看预处理、识别、匹配、保存和总耗时；`ocr.completed`审计中保存前面三个阶段耗时，便于区分模型等待与本地处理。

部署后测量：完整上下文97873字节，精简接口1839字节，减少约98.1%；服务器内部精简接口4次为11/8/8/7毫秒。同批10行材料匹配逐行读取174毫秒，复用目录14毫秒。公网模拟手机页面包含500毫秒空闲等待，约0.85至1.88秒；网络和冷启动有波动，不能据此承诺用户真机整体提速比例。

## 迁移与回退

迁移`0004_custom_roles`新增`CustomRole`表、`ProjectMembership.customRoleId`空列及索引/外键，不重置既有账号、项目、单据或图片。部署先完整备份，再用新镜像运行`prisma migrate deploy`，完成后切换应用和Worker。不得运行初始化、演示数据导入或重建数据库代替迁移。

旧镜像不认识自定义角色，可能把其兼容字段误当普通员工。回退旧应用前必须检查`ProjectMembership`中非空`customRoleId`数量：零时可回退Web/Worker并保留新增表列；非零时不能直接切回旧镜像，应先隔离这些账号访问并制定授权迁移方案。不要自动清空角色授权或恢复整库，数据库恢复需要独立依据和授权。

测试使用本地独立数据库，页面验收临时账号和角色已清除。服务器备份、私有会话、截图及诊断原始数据不进入Git。部署镜像、实际提交、源包摘要、备份和数据保留证据见发布记录；只有本地Git，没有远程仓库。
