## 本地运行

需要 Node.js 22.5 以上。当前工作区已验证 Node.js 24。

```powershell
$env:npm_config_cache=(Join-Path (Get-Location) '.npm-cache')
npm install
npm run dev
```

打开 <http://localhost:3000>。本地不配置 `DATABASE_URL` 时，系统使用嵌入式 PostgreSQL（PGlite），数据在 `.data/pglite/dev`；首次请求会自动建表并写入演示数据。

演示账号：

| 角色 | 员工号 | 密码 | 权限 |
| --- | --- | --- | --- |
| 系统管理员 | `admin` | `admin123` | 全公司维护、审核、导出、强制通过 |
| 项目主管 | `supervisor` | `super123` | 审核四个演示项目点 |
| 项目采购 | `site_sh` | `site123` | 上海总部食堂上传与校正 |
| 财务只读 | `finance` | `finance123` | 全公司查看和导出 |

本地 `OCR_MODE=mock` 不会读取图片内容，结果故意包含“青莱 / 士豆”等手写错字，用于验证候选高亮和确认新建。正式识别必须切换到 `aliyun`。

## 正式识别配置

在 `.env` 或云端环境变量中配置：

```dotenv
OCR_MODE=aliyun
DASHSCOPE_API_KEY=...
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_VL_MODEL=qwen3.6-flash
```

识别流程：

1. 图片旋转、缩放及灰度预处理后，每页只向现用 Qwen3.6-Flash 发送一张图片、一次请求，同时提取全部字段；无固定二次校读或传统表格OCR。1–5页每次识别分别需要1–5次模型请求。
2. 提示模型沿真实行格定位单位、按笔画读取手写品名，规格跟随单位。手写、缺少字段置信度、单位空缺或不确定时显示核对提醒，置信度上限0.85；低置信度仍只提醒。名称末尾明确的数量单位与数量吻合时本地拆分，如“鸡排2件”显示品名“鸡排”、单位“件”。模型可能高置信度读错，折痕单位仍需逐行核对。
3. 原单日期必须同时有纸上完整年月日原文、明确置信度和一致的标准日期。缺年份、模糊、与原文不一致时不自动覆盖新建时选择的日期，并显示核对提醒；忽略拍摄水印。
4. 数量、单价和行金额分别照抄，保留原单抹零；原单总价仍按各张明确合计相加，不用明细汇总代替。多页任一页失败不保存部分结果，主模型失败可重试或手工录入。
5. `OCR_MODE=aliyun` 为兼容已有部署保留的正式识别开关，实际仅请求百炼；不再需要传统OCR的AccessKey或额度。OSS存储使用独立的`OSS_*`配置。低置信度不是实际准确率，结果仍需人工核对。

新任务失败后不自动重试，可在单据页主动重试或手工录入；主动重试会重新计量。此前已经进入队列的旧任务仍携带旧重试次数。每页一次并不表示免费；超时请求也可能计费。26张本轮输入85,150、输出19,360 Token，按官方中国内地标准单价估算0.241572元，实际以账单为准。对照、费用及局限见[维护说明](docs/ocr-single-2026-10-31/使用与维护.md)。

识别最终准确率必须在至少 30 张真实脱敏手写单上验证，品名匹配、数量、单价、行金额、整单总价、日期逐字段达到 95% 以上。Mock 结果不计入验收。

## 生产部署

### 方式一：Docker Compose

```bash
cp .env.example .env
docker compose up -d --build
```

Compose 会启动 PostgreSQL、Redis、Web 和 OCR Worker，并执行 Prisma 迁移。正式环境必须修改 `SESSION_SECRET`、`POSTGRES_PASSWORD` 和 `APP_URL`。
Compose 默认 `DEMO_MODE=true` 方便试运行；正式上线前改为 `false`。

### 方式二：阿里云

推荐资源：

- ECS：2 vCPU / 4 GB，运行 Web 与 Worker。
- RDS PostgreSQL：2 vCPU / 4 GB，生产数据库。
- Redis：1 GB，OCR 异步队列。
- OSS：私有 Bucket，原图和增强图存储。
- Nginx/ALB：HTTPS、域名、80MB 请求体。
- SLS/ARMS：错误日志、OCR 失败率、队列积压和 5xx 告警。

生产环境变量：

```dotenv
APP_URL=https://你的已备案域名
SESSION_SECRET=至少32位随机字符串
DEMO_MODE=false
DATABASE_URL=postgresql://...
REDIS_URL=redis://...
STORAGE_DRIVER=oss
OSS_REGION=oss-cn-hangzhou
OSS_BUCKET=...
OSS_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
OSS_ACCESS_KEY_ID=...
OSS_ACCESS_KEY_SECRET=...
```

首次上线创建管理员：

```bash
ADMIN_EMPLOYEE_NO=admin ADMIN_PASSWORD='至少8位强密码' ADMIN_NAME='系统管理员' npm run create-admin
```

管理员登录后，在“系统设置 → 项目点”核实项目，在“系统设置 → 员工”维护需要的账号和项目权限；单人试用无需另外创建员工。“原材料管理”维护材料，“合同主数据”维护供应商、合同价及三表导入。`DEMO_MODE=false` 时系统不会自动写入演示账号或演示单据。

OSS Bucket 必须保持私有，并为浏览器直传配置最小 CORS 规则：

- 允许来源：`https://你的已备案域名`
- 允许方法：`PUT`、`GET`
- 允许请求头：`Content-Type`

## 数据与安全

- 图片通过短时签名 URL 或受权限保护的文件接口访问。
- 所有 API 在服务端校验项目点权限，财务角色只读。
- 单据修改携带版本号，并发修改返回 409。
- 主管修改、强制通过和主数据合并全部写入审计日志。
- 金额使用 PostgreSQL 定点小数；时间存 UTC，界面使用 Asia/Shanghai。
- 在线保留原图与结构化数据 5 年；建议 RDS 每日备份保留 30 天，并每月导出加密快照到 OSS 归档。
